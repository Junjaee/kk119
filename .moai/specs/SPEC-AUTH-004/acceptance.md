# SPEC-AUTH-004: 계정 잠금 및 자동 해제 - 인수 기준

## 개요

계정 잠금 및 자동 해제 시스템의 상세한 인수 기준 및 테스트 시나리오입니다.

---

## 핵심 기능 인수 기준

### AC-001: 5회 실패 시 계정 잠금

**Given** (전제 조건):
- 사용자 계정이 정상 상태이다
- 올바른 비밀번호는 `correct_password`이다

**When** (실행):
- 사용자가 잘못된 비밀번호로 5회 연속 로그인을 시도한다

**Then** (결과):
- 첫 4회 실패 시: "잘못된 비밀번호입니다. (남은 시도: X회)" 메시지 표시
- 5회 실패 시:
  - 계정이 잠긴다
  - "계정이 30분 동안 잠겼습니다." 메시지 표시
  - 잠금 이메일이 발송된다
  - `account_locks` 테이블에 잠금 기록이 생성된다
  - `unlock_at`은 현재 시간 + 30분이다

---

### AC-002: 잠긴 계정 로그인 시도

**Given** (전제 조건):
- 사용자 계정이 잠긴 상태이다
- 자동 해제까지 25분 남았다

**When** (실행):
- 사용자가 올바른 비밀번호로 로그인을 시도한다

**Then** (결과):
- 로그인이 거부된다
- "계정이 잠겼습니다. 25분 후 다시 시도하세요." 메시지 표시
- 비밀번호 재설정 링크가 표시된다

---

### AC-003: 30분 후 자동 해제

**Given** (전제 조건):
- 사용자 계정이 30분 전에 잠겼다
- Cron Job이 정상 동작 중이다

**When** (실행):
- 30분이 경과한다
- Cron Job이 자동 해제를 실행한다

**Then** (결과):
- 계정 잠금이 자동으로 해제된다
- `account_locks` 테이블의 `unlocked_at` 필드가 업데이트된다
- 사용자는 정상적으로 로그인할 수 있다

---

### AC-004: 로그인 성공 시 실패 기록 삭제

**Given** (전제 조건):
- 사용자가 3회 로그인 실패 기록이 있다
- 계정은 아직 잠기지 않았다 (5회 미만)

**When** (실행):
- 사용자가 올바른 비밀번호로 로그인에 성공한다

**Then** (결과):
- 로그인이 성공한다
- `failed_login_attempts` 테이블에서 해당 사용자의 모든 실패 기록이 삭제된다
- 다음 로그인 실패 시 카운트가 1부터 다시 시작한다

---

### AC-005: 관리자 수동 해제

**Given** (전제 조건):
- 사용자 계정이 잠긴 상태이다
- 관리자가 로그인되어 있다

**When** (실행):
- 관리자가 "계정 잠금 해제" 버튼을 클릭한다
- 해제 사유를 입력한다 ("사용자 요청")

**Then** (결과):
- 계정 잠금이 즉시 해제된다
- `account_locks` 테이블의 `unlocked_at`과 `unlocked_by` 필드가 업데이트된다
- 사용자는 즉시 로그인할 수 있다
- 실패 시도 기록이 모두 삭제된다
